## 1. 施工公式与复用范围

**个人作品集 M1 = 保全并复用现有源码 + 已选 M0 视觉 + 有事实边界的案例数据 + 真导航/页面状态 + 旧 URL/SEO 兼容 + 同一构建的稳定预览 + 图像对照验收。**

网站核心是内容与导航，不是 AI 推理引擎。假/真边界指概念素材、外链门户 demo 与真实项目证据；不要为套用 AI 产品公式新增假后端、数据库、CMS、账户或支付。

- `REUSE`：现有 Next.js **16.1.6**、React **19.2.3**、TypeScript、Tailwind **4**、仓库内内容、页面路由、联系/CV 入口和既有托管安排。版本据当前 `package.json`，M1 开工再核对锁文件，不顺手升级依赖。
- `ADAPT`：首页、四案例页、About/历史作品入口、移动导航、状态/示意标识、metadata 和 URL 兼容。
- `CUSTOM`：准确案例摘要、个人贡献、素材来源/公开边界及本作品集的最薄内容字段。
- `DEFER`：新模板迁移、MDX/blog、CMS、登录、数据库、AI API、联系表单后台、新统计/遥测、收费与公司系统接入。

沿用 [M0 workflow v1](m0-portfolio-workflow-v1.md) 的复用研究，不在同阶段重选底盘。官方 Portfolio Starter 仅是可参考的局部模式，不整包覆盖现站，也不默认带入其依赖或 Analytics。新依赖、内容系统、数据边界或发布目标实质变化时，才重新研究并形成 v2。

## 3. 最短施工顺序（批准 M1 后执行）

1. **先保全真实源码基线。** 主目录 `E:\gitclone\deshengkong-site` 有既有未提交 AI 重定位稿；当前 M0 worktree `E:\gitclone\deshengkong-site-m0-preview` 从跟踪基线 `8bbc53e` 建立，不包含该稿。先只读核对两处 status/diff/HEAD，保留完整变更清单与可恢复副本，再在授权的实现 worktree 中合入经核对的稿件。不得用旧 worktree 整份覆盖主目录，不自动 stash/reset/清理。记录采用了哪些原稿文件与保全位置；commit/push 只按相应授权执行。
2. **形成复用起点。** 核对现有组件、内容模型、路由、静态资源和锁文件，确认 M0 原 PNG、SVG、[visual-contract](../design/m0-portfolio-v2/visual-contract.md) 与 [tokens](../design/m0-portfolio-v2/design-tokens.json)。保留旧作品/URL，明确新增四例的 slug 与联系/CV 目的地；不换框架。
3. **内容先行，再适配样式。** 用一个类型明确的内容源记录 title、status、summary、contribution、scope、visual provenance 与 optional demo URL；不重复复制页面文案。把首页/案例/状态/联系等做成可复用组件，按合同落地 CSS。概念图片每幅保留披露，不从内部档案自动搬图。
4. **补齐真实浏览路径。** Work/Explore → 精选；All projects → 包含历史作品的集合；卡片 → 案例；About → 关于；联系/CV → 既有目的地；门户 View demo → 经核对的公开演示并提示离站。实现 mobile menu、可见 hover/focus、外链语义、缺失素材回退及未知案例 404。插画中的 portal 按钮没有网站功能，不做成伪可点控件。交互表是待实现映射，验收后再另存交互合同，不能预写 APPROVED。
5. **本地验证与对照。** 在用户本轮选定的环境执行 `npm run lint`、`npm run build`，记录命令、退出码与原始结果；浏览器检查 `320/390/768/1024/1440` 宽、键盘/移动菜单/所有主链接/404/旧 URL/CV/缺图回退。记录所选字体名称、版本/度量和浏览器环境，以同一字体环境、显式 hero 换行、固定容器对照 M0 的版式与密度，先修明显差异。原 PNG 字体未被精确识别，跨机原样字体复现未验证；不下载或嵌入未核授权系统字体，也不以 fallback 名称冒称已等价。无需为文案/样式写镜像式单元测试。
6. **同产物分享。** 在明确授权的独立 preview 目标发布步骤5的同一构建产物；记录 source commit（或精确源码快照）、构建标识/文件 hash、预览 URL。托管若只接受重新构建，先解决可复现构建与逐项 hash 对照，不能把“同 commit”直接当“同产物”。线上再核对相同尺寸、资源、链接与截图；不重新生成 UI，不部署个人主域名。
7. **交回验收。** 提供本地源码、准确内容/素材清单、同产物预览、对照截图、差异记录、控件结果表与未解决项。用户确认的是实际 M1；不能仅凭 build 成功、M0 图片好看或 SVG 可打开写“网站完成”。中央状态及合同指针由 Integrator 更新。

## 4. 环境、验收与停止线

当前未选择重负载/常驻测试环境。**在 dev server、完整浏览器/E2E、明显负载构建或服务器运行前，先由用户选择本机或服务器专用 VM**；只读检查与文档核验可继续。未选时不安装 Docker/运行时、不启动常驻进程、不创建 VM。若选服务器，不得复用生产服务或导入公司凭据。

M1 最低闭环：访客能从首页进入四案例、看懂个人贡献和阶段、返回/查看历史作品、打开联系与 CV；手机全部可用；门户外链明确是 demo；缺图和无效 URL 有诚实结果；所有概念素材有标识；稳定预览与已验本地产物一致。不会因为没有数据库、假 AI 引擎或后台而判不完整。

**当前停止线：保存合同与 SVG 后等待用户对施工步骤的决定。** 后续 M1 即使获批，也不自动授权主域名发布、客户/公司资料公开、新服务、付费平台、生产连接或额外测试设备。

## 5. 回退与退出

- 原主目录稿件、旧作品和 v1 PNG 保留；UI 适配失败先回到保全基线或修复最小差异，不转投新平台重新生成。
- 事实不够的内容缩小主张、保持 in development/demo；素材缺失用带标识的既有概念素材，不编造照片、推荐语、数字或验收。
- 内容/源码/合同/素材清单都留在项目和 Git；既有托管只是分发方式，可迁移，不把云会话或按次 Credit 当作者工具。
- 验收失败保持预览与失败证据，不提升阶段；部署失败不影响保留本地产物，也不直接改主域名作临时替代。
